# Risk Register

| Risk | Impact | Control | Status |
|---|---|---|---|
| Duplicate/fake freelancer accounts | account bans, lost funds, damaged trust | one legitimate account; no decoy bidding | controlled by policy |
| Account age/legal-owner mismatch | failed verification or account loss | use only approved legal format; obtain platform response | open |
| Prohibited automatic bids/messages | restriction or ban | drafts/analytics only until official permission | controlled by policy |
| False team/project claims | client disputes and profile block | evidence registry and truth review | controlled by policy |
| Secrets committed to Git | credential theft and service compromise | `.gitignore`, secret storage, review checklist | active control |
| One giant context file becomes stale | contradictory agent behavior | structured brain files and decision log | controlled by structure |
| Chat history becomes source of truth | context drift and lost decisions | repository is canonical | controlled by structure |
| Too many service lanes create a vague profile | low trust/conversion | broad profile, narrow per-opportunity proposal and case | monitor in Stage 1 |
| Low-price projects become unbounded | losses and missed deadlines | explicit scope/revisions/payment reason | active control |
| 18-hour capacity becomes assumed baseline | overpromising and bad reviews | conservative scheduling | active control |
| Two mailboxes create duplicate leads | duplicate replies or missed state | normalized lead ID and mailbox/source fields | implementation needed |
