# Service Matrix

## Discovery principle

All relevant service lanes start without a fixed priority. The system collects real market evidence before shifting effort.

| Service lane | Example work | Evidence to prepare | Market metrics |
|---|---|---|---|
| AI agents | research, assistants, workflow agents | architecture, demo, screenshots, result | opportunities, replies, funded value |
| Automation | email, reporting, operations, monitoring | before/after process, integrations | response rate, delivery hours, margin |
| Telegram bots | lead bots, CMS bots, monitoring bots | live flow, commands, backend | replies, project value, repeat work |
| CRM/internal tools | forms, pipelines, dashboards | workflow diagram, UI, backend | conversion, complexity, margin |
| Websites | landing, clinic, portfolio, business site | live links, screenshots, mobile view | win rate, time to deliver, reviews |
| MVP/web apps | frontend, backend, accounts, APIs | demo, repo proof, test evidence | project value, risk, duration |
| AI content | images, video, content pipelines | before/after, consistency, workflow | demand, revision load, margin |
| Audio processing | cleanup, QA, transcription pipelines | audio samples, reports, tests | demand, compute cost, delivery time |
| SEO/GEO/GBP | local search and content systems | audited case, measurable data | retention, monthly revenue, proof |
| Data/monitoring | parsers, price monitoring, alerts | sample report, reliability proof | repeatability, support load, margin |

## Allocation rule

Do not reduce a lane merely because it appears less prestigious. Reduce or increase effort only after comparable data exists.
