# Business Rules

## Revenue hierarchy

Use this priority order when comparing work:

1. Protect accounts, client trust, funds and delivery capability.
2. Win legitimate funded work.
3. Complete work successfully and obtain payment/review.
4. Improve repeatability and operating margin.
5. Add features only when they support the preceding goals.

## Every task needs a money path

Before starting a task, record:

- target funnel stage
- expected measurable effect
- evidence that the task is needed
- smallest useful output
- stop condition

Reject or postpone work that has no credible connection to revenue, conversion, delivery reliability, compliance or learning from real market data.

## Project modes

### CASH

Accept primarily for direct profit and fast payment.

### REPUTATION

Accept at a reduced price when the likely review, rating or verified platform history has clear value.

### STRATEGIC

Accept when the result creates a reusable case, unlocks a new category or has a credible repeat-work path.

Each project must have one primary mode and a written reason.

## No fixed minimum price

A project can be accepted at any price when the commercial reason is explicit and the scope is controlled.

A low-price project must not include:

- undefined unlimited revisions
- unpaid full implementation tests
- unbounded support
- unclear ownership of assets
- off-platform payment where the platform prohibits it
- hidden costs that make completion impossible

## Proposal policy

For each opportunity, generate multiple internal variants if useful, but send only one truthful proposal from the legitimate account.

The selected proposal should contain:

- direct understanding of the task
- one relevant proof point
- a short execution approach
- realistic price and deadline logic
- one useful clarification only when necessary
- a low-friction next step

Never use multiple identities to manufacture contrast.

## Experiment policy

A/B tests occur across comparable opportunities over time, not through simultaneous deceptive bids on the same project.

Track at minimum:

- template/version
- service lane
- source
- response
- qualified response
- funded outcome
- project value
- delivery result
